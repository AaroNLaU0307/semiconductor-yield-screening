# Predictive baseline report

Generated by `scripts/run_pipeline.py`. Contains the second and last declared holdout read (DECISIONS.md D12). The grid point and the decision threshold were both selected on train out of fold predictions before the holdout was scored.

## 1. Headline

**The model is weak, and the holdout interval does not exclude the no-skill floor.** Holdout PR-AUC is 0.062 (95 percent interval 0.050 to 0.098) against a no-skill floor of 0.055. The point estimate is about 1.1 times the floor, but with 26 holdout failures the interval is wide enough to include no skill at all, so this should not be read as a working detector.


Accuracy is not used as a headline anywhere, because predicting pass for every lot scores 94.5% accuracy on this holdout while catching none of the failures. That number is in the table below only to make the point.


## 2. Holdout metrics

| L2 logistic regression | 0.1037 | 0.0561 to 0.2388 | 0.5272 | 0.2308 |

No-skill PR-AUC is the holdout positive rate, 0.0552. Every precision-recall curve in this project is drawn with that line so a reader can see how much of the curve is skill.


**The secondary model scored higher, and it is deliberately not promoted.** L2 logistic regression reached PR-AUC 0.104 against 0.062 for the declared primary. DECISIONS.md D9 named the gradient boosting model as primary before any holdout record was read, and D12 forbids changing that on the basis of a result. Swapping the headline to whichever model won on the evaluation set is model selection on the holdout, which is the exact error this project is built to avoid.

The comparison is also not resolvable at this sample size. The two intervals overlap substantially (0.050 to 0.098 against 0.056 to 0.239). ROC-AUC ranks the two models the other way round (0.539 for the primary against 0.527 for the secondary), which is a direct sign that the ordering is noise rather than a real difference in skill. With 26 holdout failures, neither model is distinguishable from the other, and the lower end of both intervals sits at or below the no-skill floor.


**Why PR-AUC and not ROC-AUC.** At a 5.5% positive rate, ROC-AUC is dominated by the true negative mass and stays flattering while precision is unusable. ROC-AUC is reported above for completeness and is never headlined.

Selected: `{'learning_rate': 0.1, 'max_leaf_nodes': 15}` plus the fixed settings `{'min_samples_leaf': 20, 'max_iter': 200, 'early_stopping': True, 'class_weight': 'balanced'}`.


**The out of fold PR-AUC is not a performance number and is not reported as one.** It is 0.120 over the 910 train records that received an out of fold prediction, and it is optimistic, because the feature screen was run on all of train rather than nested inside each fold. Nesting the screen would leave roughly 62 failures per fold to screen 424 features, which is too thin to be stable. The consequence is accepted and bounded: this number selects among the declared grid and does nothing else. The holdout PR-AUC of 0.062 pays for the screen in full, because no holdout record took any part in screening.

**Reading the sweep.** At the base ratio the model flags 7 lots and catches 0 of 26 failures. Across the entire sweep the best precision achieved at any threshold is 0.0690, against a base failure rate of 0.0552, so flagged lots are barely more likely to fail than unflagged ones at any operating point. Full recall first appears at a cost ratio of 46 to 1, and it is reached by flagging 471 of 471 lots, that is, every lot. At that point precision equals the base failure rate exactly, which is the arithmetic signature of a model contributing nothing: the only way it catches every failure is to stop discriminating at all.

**This ranks association, not causation.** Permuting a column measures how much the fitted model leans on it, which reflects both the process and every correlation among the sensors. A sensor can rank high because it proxies another, and a genuinely important sensor can rank low because a correlated twin covers for it. Nothing in this table establishes that changing a sensor would change yield.


## 7. Comparison with published numbers on this dataset

SECOM is heavily used and many published analyses report far stronger results. Before comparing, check the protocol: random cross validation on time ordered records, oversampling applied before the split, or feature selection performed on the full dataset all inflate the reported number without improving the detector. The figures here come from a chronological split with every transform and the entire screen fitted on train alone, so they are not comparable to numbers obtained under those protocols and are not offered as a competitor to them.
